Add PayPal. Then try to rob it.

AI agents now build shops, and soon they will shop in them. One mistake in a checkout is free money for the first agent that finds it. Heistproof lets an AI coding agent add PayPal to a shop, buys from the shop for real in PayPal's sandbox, then runs ten robberies on it. The checkout ships only when every robbery fails.

    How a run goes

    1. AddAn AI coding agent adds PayPal, Venmo and Pay Later to the shop, working from APIMatic's PayPal plugin. It writes a plan before any code.
    2. BuyA scripted browser (no AI) buys a $49 hoodie for real in PayPal's sandbox and checks that PayPal will charge exactly the bag total before it approves.
    3. RobTen scripted robberies try to steal from the running shop: a $0.01 price, payment claimed for an order nobody approved, forged and replayed messages from PayPal, a declined card, a double capture, and more.
    4. FixAnything that worked for the thief goes back to the coding agent with PayPal's own answer (status, issue, debug id), and the whole check runs again.
    5. ShipA branch with the change, its tests and the evidence report. A pull request is opened only when the shop is on GitHub and the checkout is safe.

    All money is PayPal sandbox money; no real money moves. The shops are sample shops kept in this repository. The robberies are deterministic scripts, not an AI; the AI is the coding agent that writes and fixes the checkout. An incomplete check is never called safe.

          What happened

            Full agent log
              Safe to ship means the real sandbox purchase went through once and all 10 robberies were blocked. Do not ship means at least one robbery worked, or the purchase itself failed. Incomplete means not every robbery could run, so there is no verdict on the rest; an incomplete check is never called safe.
              Each robbery is a real attempt on the shop through PayPal's sandbox, not a simulation. Blocked: the shop refused it. Robbed: it worked, and the shop would have lost money or goods. Not run: it was not part of this recording. Skipped: it could not run on this shop. Open a row for the result, the screenshots and PayPal's own ids.
              Everything here comes from PayPal's sandbox, so no real money moves. PayPal order: PayPal's id for the purchase. Capture: the moment PayPal actually took the money. Signed webhook: PayPal's own "payment completed" message, its signature checked with PayPal. The raw answers are the recorded calls, byte for byte.
