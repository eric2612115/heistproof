Add PayPal. Then try to rob it.

AI agents now build shops, and soon they will shop in them. One mistake in a checkout is free money for the first agent that finds it. Heistproof robs a PayPal checkout first: it buys from the running shop for real in PayPal's sandbox, tries ten scripted robberies, lets an AI thief invent more, and checks the shop's books against PayPal's own records. Its AI coding agent can add PayPal and fix whatever gets through; the checkout ships only when every robbery fails.

    How a run goes

    1. AddAn AI coding agent adds PayPal, Venmo and Pay Later to the shop, working from APIMatic's PayPal plugin. It writes a plan before any code. Or skip this step and check a checkout you already have.
    2. BuyA scripted browser (no AI) buys from the shop for real in PayPal's sandbox and checks that PayPal will charge exactly the bag total before it approves.
    3. RobTen scripted robberies try to steal from the running shop: a $0.01 price, payment claimed for an order nobody approved, forged and replayed messages from PayPal, a declined card, a double capture, and more.
    4. AI thiefA model that sees only what any visitor sees invents robberies of its own; Heistproof carries them out through a few fixed moves that can reach only the shop under test.
    5. BooksEvery order the shop calls paid must be backed by a completed PayPal capture that covers it, one capture per order. PayPal's records decide every robbery, never the thief.
    6. Fix, then shipWhat got through goes back to the coding agent with PayPal's own answer (status, issue, debug id), and everything runs again. A pull request only when the checkout is safe.

    All money is PayPal sandbox money; no real money moves. The shops are sample shops kept in this repository; the hand-written ones have planted mistakes. The ten scripted robberies are deterministic; the AI thief is a model, and PayPal's records, not the model, decide what got through. An incomplete check is never called safe.

            Full agent log
              Safe to ship means the real sandbox purchase went through once, all 10 scripted robberies were blocked, nothing the AI thief tried got through and the shop's books match PayPal's records (when the AI thief did not run, the verdict says so). Do not ship means at least one robbery worked, or the purchase itself failed. Incomplete means not every robbery could run, or the books could not be matched, so there is no verdict on the rest; an incomplete check is never called safe.
              Each robbery is a real attempt on the running shop through PayPal's sandbox, not a simulation. Blocked: the shop refused it. Robbed: it worked, and the shop would have lost money or goods. Skipped: it could not run on this shop, so it was not blocked either. Not run: it was not part of this recording.
