# Prior art: what has been done, and what has not

**If you are reviewing this project and think it has been done before: parts of it have. Read this table first, then decide what has not been done.** Every row names what the other work does, what it does not do, how Heistproof differs, and the test or recording in this repository where the difference can be checked.

| # | Prior work | What it does | What it does not do | Heistproof's difference | Check it in this repo |
|---|---|---|---|---|---|
| 0 | ["I told an AI agent to rob my store. It found 39 ways to do it"](https://hackernoon.com/i-told-an-ai-agent-to-rob-my-store-it-found-39-ways-to-do-it) (HackerNoon, September 2026) | A store owner pointed a coding agent at their own x402/USDC store, sandboxed; findings logged with reproduction steps and fixed with regression tests. | It is one audit of one store, on a crypto rail, not a tool others can run; the agent's findings are judged by the author; no PayPal. | A reusable tool for any PayPal checkout: scripted robberies as a fixed regression set, an AI thief for the unknown, and PayPal's own records, not the attacker, decide each result. | `npm run demo`; `test/attacks/one-bug.test.ts` |
| 1 | [OWASP Web Security Testing Guide, WSTG-BUSL-10 "Payment Functionality"](https://github.com/OWASP/wstg/blob/master/document/4-Web_Application_Security_Testing/10-Business_Logic/10-Payment_Functionality.md) | The reference list of payment tests: quantity, price and currency tampering, and payment flows that trust the browser instead of the gateway's result. | A guide for a human tester; it runs nothing. | Runs these tests automatically, with real PayPal sandbox purchases, on every change. Each robbery maps to one of them or to a PayPal safeguard (see the README's robbery table). | `src/attacks.ts`; `test/attacks/offline.test.ts` |
| 2 | AI agents for business-logic testing, such as Ethiack's [Hackian](https://ethiack.com/news/product/hackian-ghosts-in-business-logic) and Escape's [business logic agent](https://docs.escape.tech/documentation/validate/business-logic-agent/) | Probe a running application's flows (cart, discount, checkout) for logic flaws. | General purpose; they do not complete purchases in a payment provider's sandbox or check the provider's own records; they run after the code exists, not while a coding agent writes it. | Runs when a coding agent adds or changes PayPal, buys for real in PayPal's sandbox, reconciles the shop's books with PayPal's order records, and sends what got through back to the coding agent. | `src/books.ts`; `src/pipeline.ts` (fix loop) |
| 3 | Dynamic scanners (for example OWASP ZAP) | Send crafted requests to endpoints, one at a time. | Do not follow a purchase from the bag to PayPal's capture, its webhooks and the shipping label. | Each robbery is a whole purchase or a whole money flow, judged by what the shop shipped and what PayPal captured. | `src/prove.ts`; `src/attacks.ts` |
| 4 | AI end-to-end QA services for checkouts | Check that a checkout works for an honest shopper. | Not adversarial; they do not try to pay $0.01, forge PayPal's events or capture twice. | Adversarial by design; an honest purchase is only the first of eleven steps. | `test/attacks/offline.test.ts` |
| 5 | Unit tests the coding agent writes for its own code | Run against a fake PayPal the agent also wrote. | Cannot see what the real sandbox does. | In our full run the agent's 23 tests passed while PayPal's sandbox refused the capture with 415; Heistproof's real purchase caught it and the agent fixed it. | the full run's report in `runs/` |
| 6 | PayPal's own sandbox tools: sandbox accounts, negative testing (`PayPal-Mock-Response`), webhook verification | The ingredients for testing an integration. | Give no verdict and try no robbery. | Uses exactly these ingredients, and turns them into a verdict that gates the pull request. | `src/paypal/proxy.ts`; `src/sandbox.ts` |
| 7 | [APIMatic's PayPal Context Plugin](https://github.com/context-plugins/plugin-marketplace/tree/main/plugins/paypal) | Gives the coding agent PayPal's API context so it writes the integration plan-first. | Does not test what the agent wrote. | Heistproof is the verifier around it. It found a real gap: following the plugin's rule to leave out optional fields made the capture send no Content-Type, which the sandbox refuses (415). | the full run's report in `runs/` |

## The claim of being first, written so it can be refuted

As of November 2026 we know of no tool that does all three of these for PayPal checkouts:

1. a coding agent adds or fixes the PayPal integration;
2. the running shop is bought from in PayPal's sandbox and robbed, by a fixed set of scripted robberies and by an AI thief that sees only what any visitor can see;
3. every result is decided by reconciling the shop's books with PayPal's own order records, and the verdict gates the pull request.

If you know one, open an issue with a link and we will add it to this table.
